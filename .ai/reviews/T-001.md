## Findings

### SHOULD
1. **Spy may leak across tests** — `random-code.generator.test.ts`, `random-otp.generator.test.ts`, `uuid.generator.test.ts`: `mockRestore()` is placed at the end of each test, so if an earlier `expect` fails, `crypto.randomInt` / `randomUUID` remains mocked for subsequent tests, causing cascading failures that are hard to diagnose. Use `afterEach(() => { vi.restoreAllMocks(); })` in each `describe` and remove manual `mockRestore()` calls.
2. **Incorrect parameter source attribution** — `argon2.hasher.ts`: "OWASP minimum recommendations for Argon2id (RFC 9106)". The 19 MiB / t=2 / p=1 configuration is from the **OWASP Password Storage Cheat Sheet**; RFC 9106 recommends a different set. Correct to cite OWASP only.

### NIT
3. `apps/server/package.json`: place `dependencies` before `devDependencies` for the conventional order.
4. `verify` swallows **all** errors, including non-malformed hash errors (e.g. broken native module). Matches the task contract, but should include a one-line comment clarifying this is intentional.

## Out-of-scope findings for T-001 (handled by Claude, not Gemini's fault)
- **Timing leak in `RequestJoin`** — when session code does not exist, the use case verifies against `DUMMY_HASH`, a non-argon2 string. With a real `Argon2Hasher`, verifying that string returns `false` in ~0.04 ms, whereas verifying a real hash takes ~28 ms (measured on this clone, default parameters). An attacker could distinguish whether a code exists or not — defeating the timing attack mitigation (ADR-004, 05-security I4). Fake hasher in unit tests has no latency so this was not exposed. → Fixed on branch `fix/join-timing-dummy-hash`: use a real argon2 hash as dummy.
- **pnpm ignores build scripts of `argon2`** (`Ignored build scripts: argon2`). Currently works because `argon2` provides prebuilt binaries for Windows/Linux/macOS x64, but should be explicitly declared in the root `package.json` (`pnpm.onlyBuiltDependencies`) — outside T-001 file scope, so Claude handles it on the branch above.
