## Findings

### MUST
1. **Returned results share arrays with configuration** — `turn-ice-server.provider.ts`, `urls: this.config.stunUrls` and `urls: this.config.turnUrls`. Tested: take result from session 1, `push` an additional `'turn:evil.example:3478'` into `urls`, and session 2 also receives that URL. `readonly` is only at type level, does not prevent runtime modification (gateway, serializer or any future code). Fix: return **copies** (`[...this.config.stunUrls]`), and copy the configuration in constructor so caller modifying the original array does not affect it either. **Add tests**: mutate `urls` of session 1 result and verify session 2 is unchanged; mutate original configuration array after creating provider and verify results are unchanged. Note existing tests use `toBe(turnUrls)` (reference comparison) — switch to `toEqual`.

### SHOULD
2. **`toThrow()` does not check error reason** — 4 tests in `constructor validation` use empty `.toThrow()`, so any error (including `TypeError` from a bug) passes the test. Check message, e.g. `.toThrow(/turnSecret is required/)`, `.toThrow(/must start with "stun:"/)`.

### NIT
3. Inline end-of-line comments in `TurnConfig` are very long; convert to JSDoc on each field.
